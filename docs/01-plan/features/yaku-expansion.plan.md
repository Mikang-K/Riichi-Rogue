# Plan: 리치마작 역 판정 확장 (yaku-expansion)

**Status**: Draft  
**Created**: 2026-05-14  
**Feature**: yaku-expansion  
**Phase**: Plan

---

## Executive Summary

| 관점 | 내용 |
|------|------|
| **Problem** | 현재 역 판정은 `칠대자`, `탕야오`, `핑후`, `또이또이`, `혼일색`, `청일색`, `역패`, `삼색동순` 정도만 지원하며, 리치마작의 주요 역과 판정 조건을 담기에는 손패 분석 정보가 부족하다. |
| **Solution** | 손패 분석 결과를 확장하고, 역 판정 컨텍스트를 도입한 뒤, 폐쇄형 손패 기준의 주요 1~3판역부터 단계적으로 추가한다. |
| **UX 효과** | 플레이어가 실제 리치마작에 가까운 조합을 만들었을 때 더 많은 역이 인정되어 전략 선택지가 늘어난다. |
| **핵심 가치** | 게임의 마작 정체성을 강화하면서도 현재 로그라이트식 점수 구조와 유물 시스템을 유지한다. |

## Context Anchor

| 축 | 내용 |
|----|------|
| **WHY** | 현재 게임은 마작패를 사용하지만 역 풀이 좁아 손패 조합의 재미가 금방 반복된다. 역을 확장하면 손패 교환 판단과 유물 선택의 의미가 커진다. |
| **WHO** | 리치마작을 아는 플레이어와, 마작을 잘 몰라도 조합 게임으로 접근하는 플레이어. |
| **RISK** | 실제 리치마작의 역은 화료 방식, 멘젠 여부, 장풍/자풍, 대기 형태, 도라, 후로 여부 등 추가 상태가 필요하다. 현재 게임 상태만으로 모든 역을 정확히 판정할 수 없다. |
| **SUCCESS** | 새 역이 테스트 가능한 순수 함수로 판정되고, 기존 점수 계산식과 UI 표시가 깨지지 않는다. |
| **SCOPE** | 1차 목표는 멘젠 14장 손패 기준 역 확장. 후로, 리치 선언, 론/쯔모, 점수표 기반 부/판 계산은 제외한다. |

## 1. 현황 분석

### 1.1 현재 구조

현재 역 판정은 `src/game.js` 안에서 다음 흐름으로 실행된다.

```text
scoreHand()
  -> analyzeHand()
  -> getYaku()
  -> yakuScore 계산
```

현재 `analyzeHand()`가 반환하는 정보는 다음 수준이다.

```js
{
  isComplete: true,
  type: "standard" | "sevenPairs" | "none",
  melds: [{ type: "sequence" | "triplet", tiles }],
  pair: "m1" | "zE" | null
}
```

### 1.2 현재 지원 역

| 역 | 현재 판정 가능 여부 | 비고 |
|----|----|----|
| 칠대자 | 가능 | 7쌍 판정 |
| 탕야오 | 가능 | 2~8 수패만 확인 |
| 핑후 | 부분 가능 | 대기 형태와 자풍/장풍 머리 조건 미반영 |
| 또이또이 | 가능 | 전부 커쯔 |
| 혼일색 | 가능 | 한 종류 수패 + 자패 |
| 청일색 | 가능 | 한 종류 수패만 |
| 역패 | 부분 가능 | 삼원패만 판정, 장풍/자풍 미반영 |
| 삼색동순 | 가능 | 같은 시작 숫자의 세 색 순자 |

### 1.3 주요 한계

1. **다중 분해 미지원**  
   `findMelds()`는 가능한 분해 중 첫 번째만 반환한다. 같은 손패가 여러 방식으로 분해될 때, 특정 역을 놓칠 수 있다.

2. **화료 컨텍스트 부족**  
   리치, 멘젠쯔모, 해저, 영상개화, 일발 등은 "어떻게 화료했는가" 정보가 필요하다. 현재는 손패와 도라만 있어 판정할 수 없다.

3. **풍 정보 부족**  
   역패의 장풍/자풍 판정에는 현재 국의 장풍과 플레이어 자풍이 필요하다. 현재 라운드 이름은 있지만 판정용 풍 상태로 모델링되어 있지 않다.

4. **대기 형태 부족**  
   핑후를 정확히 판정하려면 양면 대기 여부가 필요하다. 현재 게임은 완성된 14장만 제출하므로 마지막 패과 대기 형태를 알 수 없다.

5. **역만관/야쿠만 미분리**  
   일반 역과 야쿠만은 중첩 처리 규칙이 다르다. 현재 `yaku` 배열은 모든 역을 같은 방식으로 더한다.

## 2. 목표

### 2.1 기능 목표

| ID | 항목 | 설명 |
|----|------|------|
| F-01 | 역 데이터 테이블 분리 | 역 이름, 판수, 게임 점수, 태그를 데이터화한다. |
| F-02 | 손패 분석 확장 | 모든 가능한 일반형 분해를 반환하도록 `analyzeHand()`를 확장한다. |

| F-04 | 판정 함수 모듈화 | 역마다 독립 판정 함수를 두고 테스트하기 쉽게 분리한다. |

| F-06 | 조건부 역은 상태 추가 후 활성화 | 리치, 쯔모, 일발 등은 컨텍스트가 생긴 뒤 켠다. |
| F-07 | UI 참조 목록 동기화 | 실제 구현된 역과 도움말 역 목록이 어긋나지 않도록 같은 데이터 소스를 사용한다. |

### 2.2 비기능 목표

| ID | 항목 | 기준 |
|----|------|------|
| N-01 | 기존 점수 구조 유지 | `scoreHand()` 반환 형태와 유물 보너스 구조를 최대한 유지한다. |
| N-02 | 테스트 가능성 | 각 역은 고정 손패 테스트로 검증 가능해야 한다. |
| N-03 | 확장성 | 새 역 추가가 데이터 + 판정 함수 추가로 끝나야 한다. |
| N-04 | 성능 | 14장 손패 기준 모든 분해 탐색은 즉시 계산 가능한 수준이어야 한다. |

## Phase 1. 기반 정리

```js
export const yakuDefinitions = {
  tanyao: { id: "tanyao", name: "탕야오", hanClosed: 1, hanOpen: 1, score: 10 },
  pinfu: { id: "pinfu", name: "핑후", hanClosed: 1, hanOpen: null, score: 12 },

```

### 3.2 타일 유틸 분리

신규 파일:

```text
src/game/tile-utils.js
```

이동 후보:

- `keyOf()`
- `parseKey()`
- `sameFace()`
- `countTiles()`
- `sortTiles()`
- 수패/자패/노두패/요구패 판정 함수

### 3.3 다중 분해 반환

현재:

```js
const melds = findMelds(nextCounts);
if (melds) return { isComplete: true, type: "standard", melds, pair: pairKey };
```

변경 방향:

```js
return {
  isComplete,
  type,
  arrangements: [
    { type: "standard", melds, pair },
    { type: "sevenPairs", pairs },
  ],
}
```

## Phase 2. 현재 상태만으로 가능한 역 확장

이 단계는 화료 방식이나 리치 선언 없이, 완성된 14장만으로 비교적 안정적으로 판정 가능한 역을 추가한다.

| 역 | 판수 | 필요 분석 | 난이도 | 비고 |
|----|----:|----|----|----|
| 일기통관 | 2 | 같은 색 123/456/789 순자 | 낮음 | 현재 멘젠만 있으므로 2판 |
| 삼색동각 | 2 | 같은 숫자의 세 색 커쯔 | 낮음 | 커쯔 패턴 |
| 삼암각 | 2 | 커쯔 3개 | 중간 | 엄밀히는 울음/론 여부 필요, MVP에서는 커쯔 3개로 단순화 |
| 소삼원 | 2 | 삼원패 커쯔 2개 + 삼원패 머리 | 낮음 | 역패와 중첩 가능 |
| 혼노두 | 2 | 모든 몸통/머리가 노두패 또는 자패 | 중간 | 치또이츠/또이또이와 주로 중첩 |
| 찬타 | 2 | 모든 몸통/머리에 요구패 포함 + 순자 1개 이상 | 중간 | 멘젠 기준 |
| 준찬타 | 3 | 모든 몸통/머리에 노두패 포함 + 순자 1개 이상 + 자패 없음 | 중간 | 멘젠 기준 |
| 량페코 | 3 | 같은 색 같은 순자 2쌍이 두 벌 | 중간 | 멘젠 한정 |
| 이페코 | 1 | 같은 색 같은 순자 2개 | 중간 | 량페코와 배타 처리 필요 |

배타 규칙:

- `량페코`가 있으면 `이페코`는 제외한다.
- `준찬타`가 있으면 `찬타`는 제외한다.
- `청일색`이 있으면 `혼일색`은 제외한다.

## Phase 3. 컨텍스트가 필요한 기본 역

게임 상태에 다음 정보를 추가한 뒤 활성화한다.

```js
{
  roundWind: "E",
  seatWind: "E",
  isClosed: true,
  winType: "draw" | "discard" | null,
  declaredRiichi: false,
  isIppatsu: false,
}
```

| 역 | 판수 | 필요한 상태 | 구현 조건 |
|----|----:|----|----|
| 리치 | 1 | `declaredRiichi`, `isClosed` | 리치 버튼/상태 필요 |
| 멘젠쯔모 | 1 | `winType: "draw"`, `isClosed` | 현재 교환 게임에 쯔모 제출 개념을 붙일지 결정 필요 |
| 일발 | 1 | `isIppatsu` | 리치 직후 교환/행동 제한 설계 필요 |
| 자풍패 | 1 | `seatWind` | 역패 확장 |
| 장풍패 | 1 | `roundWind` | 역패 확장 |
| 더블리치 | 2 | 첫 순서 정보 | 현재 게임 구조에서는 후순위 |

검토 결과, 이 단계는 UI/룰 변경이 섞이므로 Phase 2 이후에 진행하는 것이 좋다.

## Phase 4. 야쿠만과 특수역

야쿠만은 일반 역과 합산 규칙이 다르므로 별도 타입으로 관리한다.

| 역 | 필요 분석 | 난이도 |
|----|----|----|
| 국사무쌍 | 13종 요구패 + 하나의 짝 | 낮음 |
| 사암각 | 커쯔 4개 | 중간 |
| 대삼원 | 삼원패 커쯔 3개 | 낮음 |
| 소사희 | 풍패 커쯔 3개 + 풍패 머리 | 낮음 |
| 대사희 | 풍패 커쯔 4개 | 낮음 |
| 자일색 | 모든 패가 자패 | 낮음 |
| 청노두 | 모든 패가 노두패 | 낮음 |
| 녹일색 | 2/3/4/6/8삭 + 발만 사용 | 낮음 |
| 구련보등 | 한 색 1112345678999 + 같은 색 추가 1장 | 중간 |

야쿠만 처리 규칙:

- 야쿠만이 있으면 일반 역은 점수 표시에서 숨기거나 보조 정보로만 둔다.
- 게임 점수는 `yakumanScore` 또는 별도 `score` 값을 사용한다.
- 더블 야쿠만은 MVP에서는 제외한다.

## 6. 구현 순서

1. `tile-utils.js`를 만들고 타일 분류 유틸을 추가한다.
2. `hand-analysis.js`에서 모든 일반형 분해와 칠대자/국사 후보를 반환한다.
3. `yaku-data.js`에 현재 역 8개를 먼저 옮긴다.
4. `yaku-rules.js`에 현재 역 판정을 이전해 동작을 맞춘다.
5. `yaku-evaluator.js`에서 배타 규칙을 적용한다.
6. Phase 2 역을 하나씩 추가하고 테스트 케이스를 붙인다.
7. `scoreHand()`가 새 evaluator를 사용하도록 연결한다.
8. 도움말 UI가 `yaku-data.js`를 참조하도록 정리한다.
9. Phase 3 컨텍스트가 필요한 역은 별도 기능으로 진행한다.

## 8. 검토 의견

### 8.1 바로 구현해도 좋은 범위

Phase 2의 `일기통관`, `삼색동각`, `소삼원`, `혼노두`, `찬타`, `준찬타`, `이페코`, `량페코`는 현재 게임 구조를 크게 바꾸지 않고 추가할 수 있다. 이 범위가 MVP 확장 1차 목표로 적절하다.

### 8.2 신중해야 할 범위

`리치`, `멘젠쯔모`, `일발`, `해저`, `영상개화`, `창깡`, `린샹` 같은 역은 손패 모양만으로 판정할 수 없다. 이 역들을 억지로 추가하면 "리치마작에 맞춘 확장"이라기보다 이름만 빌린 보너스가 될 위험이 있다.

### 8.3 가장 먼저 해결해야 할 구조적 문제

다중 분해 탐색이 최우선이다. 역을 단순 추가하면 일부 손패에서 첫 번째 분해 결과 때문에 `이페코`, `량페코`, `찬타`, `삼색동순` 같은 역을 놓칠 수 있다. 역 판정 확장은 손패 분석 리팩토링과 함께 가야 한다.

### 8.4 추천 범위

이번 작업은 다음 범위로 제한하는 것을 추천한다.

1. 현재 역 판정을 새 구조로 옮긴다.
2. 모든 가능한 손패 분해를 반환한다.
3. Phase 2 역을 추가한다.
4. 컨텍스트가 필요한 역은 설계만 남기고 구현하지 않는다.

이렇게 하면 실제 리치마작에 더 가까워지면서도, 현재 로그라이트식 게임 흐름을 흔들지 않고 안정적으로 확장할 수 있다.
